What Changed in v4
Findings from the Plan Review
Days 30-100 were rebuilt to fit about 250-400 hours: fewer topics, more depth, real users, honest metrics.

Eval-first from Day 30

ADDED

Write the gold set before the pipeline, calibrate your judge against hand labels, and gate CI on scores (Days 30, 43-46).

Real users & failure taxonomy

ADDED

10+ real users, read every log, categorize failures and publish what broke (Days 40, 47-48).

Async Python & Postgres/pgvector

ADDED

Concurrency for LLM backends and the relational database most companies already run (Days 32, 41).

Text-to-SQL & structured extraction

ADDED

A very common business use case, with its own eval set (Day 53).

Two tracks: job + customer pilots

ADDED

From Day 55, targeted applications and customer conversations; decide on Day 70 using real signals.

GraphRAG / Neo4j

CUT

Removed: rarely needed at junior level and hard to evaluate. Add RAG tricks only if the eval shows lift.

Framework stacking & multi-agent

CUT

One orchestration choice, single agent by default. Google ADK and the Whisper/VLM day are dropped unless your project needs them.

Fine-tuning, semantic caching, cloud ceremony, application counts

SHRUNK

Fine-tuning is a 2-day experiment; semantic caching is knowledge only; cloud deploy takes about 1.5 days; track replies, not 100 applications.
